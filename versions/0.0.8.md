# Version 0.0.8

Released: 2026-08-08

## Summary

Version 0.0.8 preserves parameter order in the JDBC tunnel and stops repeating DDL work on every JDBC call. Table and schema creation
now happen once per tunnel instance instead of on each write, notice write and modification marker read.

## Added

- `ConfigTunnelJdbc.Def.colOrder` and `ConfigTunnelJdbcBuilder.colOrder(...)` / `colOrder()` for the parameter order column, defaulting
  to `order_index`.
- `order_index INT NOT NULL DEFAULT 0` in PostgreSQL and MariaDB table creation.
- Automatic `ALTER TABLE ... ADD COLUMN` of the order column when an existing JDBC table does not have it yet.
- JDBC tests covering explicit ordering:
  - reads follow the order column, not the parameter name
  - writes store order indexes `0..n` and reads give the parameters back in the written order

## Changed

- `ConfigTunnelJdbc.write` stores the configuration row with order `0` and parameters with orders `1..n` in `Conf.params` order.
- `ConfigTunnelJdbc.read` sorts by the order column first and by the parameter name only as a deterministic fallback, so parameter
  order written to the database is the order read back.
- `ConfigTunnelJdbc` calls `createTableIfNotExists()` only once per tunnel instance. `write`, `writeNoticeLines` and
  `modificationMarker` go through an internal double-checked `createTableIfNotExistsOnce()` guard instead of running table DDL on
  every call.
- `ConfigTunnelJdbc.createSchemaIfNotExists(...)` runs `CREATE SCHEMA IF NOT EXISTS` only once per tunnel instance; later calls return
  immediately. The check for a schema-qualified table name still happens first, so unqualified table names never touch the database.
- Both guards use `AtomicBoolean` with a synchronized block, so concurrent first calls create the table or schema exactly once.
- Published POM `url` for all three modules is now `https://pompei.kz/program/kz-pompei-hotconfig` instead of the `programs/` path.
- README documents that parameter order is stored in `colOrder`.

## Migration Notes

- Existing JDBC tables get the order column added automatically on the first read. Parameters already stored keep order `0` and are
  returned sorted by name until the configuration is rewritten.
- If the database user may not run `ALTER TABLE`, add the column manually before upgrading:

  ```sql
  ALTER TABLE hotconfig ADD COLUMN order_index INT NOT NULL DEFAULT 0;
  ```

- To use a different column name, configure it on the builder:

  ```java
  ConfigTunnelJdbc tunnel = ConfigTunnelJdbc.builder()
    .connectionGet(() -> dataSource.getConnection())
    .tableName("hotconfig")
    .colOrder("param_order")
    .build();
  ```

- The create-once guards live in the tunnel instance. A tunnel created after the table was dropped externally will not recreate it
  until a new tunnel instance is built.
